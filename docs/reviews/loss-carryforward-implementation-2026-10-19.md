# تنفيذ الخسائر الشهرية والمرحلة

التاريخ: 2026-10-19. التنفيذ محلي، مع افتراض المستخدم المعتمد: التطبيق جديد ولا توجد بيانات أعمال قديمة يلزم تحويلها. لا يتضمن هذا العمل مسح قواعد البيانات أو نشرًا على Railway أو اتصالًا بقاعدة Neon.

## القاعدة المنفذة

```text
نتيجة النشاط = صافي المبيعات - مصروفات التشغيل - مصروفات الإنتاج
خسارة الشهر الحالي = min(نتيجة النشاط, 0)
صافي النتيجة = نتيجة النشاط + الخسارة الداخلة الموقعة
الخسارة المرحلة للتالي = min(صافي النتيجة, 0)
القابل للتوزيع = max(صافي النتيجة, 0)
```

الخسائر أعداد صحيحة سالبة أو صفر، والأموال بوحدات صغيرة. إجمالي الفاتورة مخزن بعد الخصم؛ لا يُخصم مرة ثانية. تبقى آلية تقريب الحصص الموجبة الحالية، وتكون الحصص الثلاث صفرًا للخسارة أو التعادل. السحوبات والإضافات اليدوية لا تدخل تكلفة النشاط ولا تُحذف عند إعادة الاعتماد.

## التغييرات

- MonthlyProfit للحساب الخالص، وProfitEngine لسلسلة الأشهر المحلية بما فيها الأشهر الخالية وانتقال السنة.
- سبعة أعمدة في MonthlyDistribution للقيم الأساسية ونتيجة النشاط والخسائر الداخلة والحالية والخارجة. SQLite بإصدار 13، ونماذج Serverpod والعميل مولدة.
- الاعتماد اليدوي/التلقائي يستدرك الأشهر المغلقة بالترتيب. التلقائي يتوقف عند التعارضات أو مزامنة معلقة أو أشهر تحتاج المراجعة.
- تعديل مصادر شهر قديم يحدّث المعاينة والتنبيه، ولا يعيد كتابة الحصص المعتمدة حتى الموافقة على إعادة اعتماد السلسلة من الأقدم.
- التسوية المحلية وoutbox والتدقيق معاملة SQLite واحدة؛ المزامنة ترتب المصادر أولًا ثم الأشهر زمنيًا.
- الخادم يتحقق من المعادلات ورصيد الشهر السابق، ويمنع استبدال CREATE مختلف للشهر نفسه. كتابة التسوية والتدقيق معاملة PostgreSQL واحدة.
- لوحة التحكم، شاشة التوزيع، تنبيه المراجعة، التقرير الشهري وPDF تعرض الخسائر. التقارير غير الشهرية تقارير نشاط ولا تكرر طرح الرصيد المرحل.
- إصلاح خصم مكرر في مبيعات اليوم، وتوحيد فحص حدود الشهر الكامل، واحتساب المرتجعات في التقرير النهائي.
- تحديث الدستور إلى 1.4.0 والخطة إلى 2.1.0 ومواصفة 010، مع توضيح أن مواصفة 006 تصف القاعدة التاريخية السابقة.

## ما جرى التحقق منه

| الأمر/الفحص | النتيجة المشاهدة |
|---|---|
| `flutter test --no-pub` داخل تطبيق Flutter | 88 اختبارًا ناجحًا |
| `dart test` داخل الخادم | 26 اختبارًا ناجحًا، تشمل integration على PostgreSQL محلية |
| `flutter build bundle --debug --no-pub` | نجاح تجميع حزمة debug، وليس إصدار APK/EXE |

اختبارات الإضافة تغطي الخسائر المتتالية، التغطية الجزئية والتامة والفائض، الحصص الصفرية، إعادة فتح SQLite، ديسمبر/يناير، rollback محلي، إعادة الاعتماد الصريح، تحديث Riverpod والتقرير بعد تعديل مصدر، فشل المصادقة مع بقاء المحلي، ترتيب رفع الأشهر، DTO، والتخزين الفعلي في PostgreSQL.

اختبارات PostgreSQL الأربع في `test/integration/monthly_settlement_endpoint_test.dart` تغطي الحفظ وإعادة CREATE المطابق/المختلف، رفض شهر سابق مفقود أو رصيد مخالف دون كتابة جزئية، rollback عند فشل التدقيق، وحدود المصادقة وصحة الحساب. يعزل `local_test_config.dart` كل اختبارات integration على `127.0.0.1:9090/motaz_app_test` حتى إذا احتوت البيئة إعدادات إنتاج. تستخدم الاختبارات rollback بعد كل حالة.

تم التأكد باستعلام قراءة من أن قاعدة الاختبار `motaz_app_test` تستخدم الترحيل `20261018235919937-loss-carryforward`، وأن الأعمدة السبعة موجودة، وأن عدد التسويات بعد الاختبارات صفر. هذا تحقق على قاعدة الاختبار فقط وليس إثباتًا بتطبيق الترحيل على Neon.

## إخفاقات عولجت

- استعلام الشهر باستخدام تحويل تاريخ SQLite لم يكن مناسبًا لبيئة Windows؛ أصبح التجميع حسب التاريخ المخزن ثم الشهر محليًا في Dart، ونجحت اختبارات السلسلة.
- عُدلت إعدادات اختبار إعادة فتح القاعدة لمنع بقاء مثيلين مفتوحين، وتصحيح تحويل DTO وفق API العميل الفعلية.
- احتاج اختبار Riverpod اشتراكات فعلية مثل `ref.watch` في الشاشة، بدل قراءة مزود Stream بلا مستمع. ثم نجح دون تأخير عشوائي.
- فشل تجميع الثيم بسبب انتقال تصدير CupertinoPageTransitionsBuilder؛ أضيف الاستيراد الصريح الصحيح ونجح التجميع.
- تعثر تشغيل Dart CLI داخل sandbox، فأُعيد بصلاحيات مناسبة. تعطل Docker مؤقتًا ثم أصبح جاهزًا، واستُخدمت خدمة `postgres_test` فقط.
- فشلت اختبارات integration القديمة بكلمة مرور لا توافق Docker؛ عُزل إعداد الاختبار في مساعد مشترك ثم نجحت الملفات منفردة ومجموعة الخادم كاملة.

## إعادة التشغيل محليًا

توليد Drift ضروري بعد checkout لأن `app_database.g.dart` ملف مولد غير متتبع. لا تضف اعتمادًا أو تغيّر نسخة Serverpod أثناء هذه الخطوات.

```powershell
Set-Location D:\dev\Motaz_App\motaz_app
flutter pub get
Set-Location motaz_app_server
serverpod generate
Set-Location ..\motaz_app_flutter
dart run build_runner build --delete-conflicting-outputs
flutter test --no-pub
flutter test --no-pub test/features/profit_distribution/data/distribution_repository_test.dart
flutter build bundle --debug --no-pub
Set-Location ..\motaz_app_server
docker compose --profile test up -d --wait postgres_test
dart test test/services test/contracts
dart test test/integration/monthly_settlement_endpoint_test.dart
dart test
```

هذه أوامر متوافقة مع المشروع. استُخدمت أيضًا المسارات المباشرة لملفات Dart وFlutter التنفيذية وsnapshot Serverpod المحلي لتجاوز قيد sandbox؛ لا يلزم ذلك عادة في الطرفية العادية. كلمة مرور قاعدة الاختبار الافتراضية من compose هي قيمة اختبار فقط، ويمكن تخصيصها عبر `MOTAZ_TEST_POSTGRES_PASSWORD` قبل إنشاء حاوية الاختبار.

## ما قبل الإصدار

1. تشغيل الأوامر اليدوية السابقة ومراجعة نتائجها.
2. تجربة Android وWindows على بيئة اختبار: حفظ دون شبكة، إغلاق وإعادة فتح، عودة الشبكة والسحب للجهاز الثاني، ثم تعديل شهر قديم وإعادة اعتماد السلسلة. لا تزال تجربة الأجهزة الفعلية والضغط المتزامن عبر اتصالات متعددة غير منفذة.
3. ترقية الجهازين معًا؛ لا تزامن عميلًا قديمًا مع أعمدة لا يعرفها. افتراض قاعدة فارغة لا يعني دعم تحويل توزيعات سالبة قديمة أو استيراد نسخة أعمال قديمة.
4. تضمين نماذج الخادم والعميل ومجلد الترحيل والسجل في التغيير. Docker الحالي ينسخ migrations ويشغّل `--apply-migrations`، لكن نشر Railway وتطبيق ترحيل Neon يحتاجان عملية نشر مستقلة؛ لم يُنفذا هنا.
5. الترحيل الإضافي: `motaz_app_server/migrations/20261018235919937-loss-carryforward/`. لا تستخدم reset SQL ولا تستبدل قاعدة حقيقية لتطبيق هذه الإضافة.
6. ملفات CI الحالية ما زالت تستخدم Flutter 3.32.8 وأمر compose القديم، ولا تولد Drift؛ تحتاج مواءمة مستقلة قبل الاعتماد على نتيجة GitHub CI. نتائج هذا التقرير من تشغيل محلي فعلي باستخدام Flutter 3.47.3/Dart 3.13.3، وليست ادعاء بنجاح CI.

الحدود المعروفة: رفع عدة أشهر ليس معاملة جماعية واحدة عبر الشبكة. تظهر السلسلة المتأثرة للمراجعة أثناء التحديث الجزئي؛ لا توجد سياسة دمج مالي صامتة. معاينة الشهر الحالي ليست اعتمادًا نهائيًا.
